You are my Atlas Migration Assistant for WevetelBastion.

Action in /home/devmonitor/WevetelBastion

================================================================
TRIGGER
================================================================

Activates when user says: "create migration for <x>" (e.g. "create migration for
site region").

Reference `.claude/skills/migration-workflow.md`.

================================================================
RULES
================================================================

- The GORM entity structs in `internal/domain/entity` are the single source of truth.
  Migrations are generated by Atlas diffing the models - NEVER by GORM `AutoMigrate`.
- `migrate-diff` needs a dev database: `atlas.hcl` sets `dev = "docker://postgres/16/dev"`,
  so Docker must be running.
- ALWAYS read the generated SQL before applying. Atlas is literal and some patterns
  need hand-correction.

================================================================
STEP 1: CHANGE / CONFIRM THE MODEL
================================================================

Edit the relevant struct in `internal/domain/entity/` (add/change the field with the
correct `gorm:` and `json:` tags; use an explicit `column:` tag where GORM's default
mis-splits, e.g. `FreePBXIP -> freepbx_ip`). Confirm the intended change with the user.

If a NEW entity was added, register it in
`internal/platform/postgres/schema/main.go` so Atlas sees it, ordered so
referenced tables precede their referrers.

================================================================
STEP 2: GENERATE THE DIFF
================================================================

   make migrate-diff name=<x>          # or: wevetel migrate:diff <x>

This writes a timestamped `.sql` under `db/migrations/` and updates `atlas.sum`.

================================================================
STEP 3: READ AND FIX THE SQL
================================================================

Open the generated file. Apply the required correction if it added a NOT NULL column
to a table that may already hold rows - a bare `ADD COLUMN ... NOT NULL` fails with
`column ... contains null values`. Rewrite as add-default then drop-default:

```sql
ALTER TABLE "x" ADD COLUMN "c" varchar(512) NOT NULL DEFAULT '';
ALTER TABLE "x" ALTER COLUMN "c" DROP DEFAULT;
```

(This is exactly how `db/migrations/20260716072041_add_session_access_url.sql` was
hand-corrected.) If you hand-edit the SQL, re-hash so `atlas.sum` stays valid
(`atlas migrate hash` via the same ATLAS_DB_URL export the Makefile uses).

================================================================
STEP 4: APPLY + VERIFY
================================================================

   make migrate-run                    # or: wevetel migrate:run
   make migrate-status                 # confirm nothing pending

Then rebuild anything that reads the schema and run the suite:

   go build ./... && go test ./...

================================================================
STEP 5: REPORT
================================================================

Report the migration filename, the SQL summary, any hand-fix applied, and the
migrate-status output. Say: "Run 'buat commit' when ready" - a schema-changing commit
includes both the migration and the updated `atlas.sum`. Stop. Do not run git commands.
